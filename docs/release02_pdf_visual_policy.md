# Release 02 PDF ビジュアル利用方針 v1.0

**作成日：** 2026-05-30  
**対象：** Release 02 PDF資料記事（note 投稿用）  
**ステータス：** 設計のみ。実装・画像抽出・記事制作はまだ行わない。

---

## 背景

Release 01（概要版）はテキスト中心の構成だった。読者が元資料の見た目・雰囲気をイメージしにくく、「実際にどんな書類なのか」が伝わりづらいというフィードバックがあった。Release 02 では PDF 記事にビジュアルを加え、資料の実在感・信憑性・読みやすさを向上させる。

---

## 1. PDF記事に入れる画像の目的

| 目的 | 説明 |
|------|------|
| **実在感の提示** | 「実際に存在する公文書」であることを読者に伝える |
| **読みやすさの向上** | テキストが続く記事にリズムをつくり、離脱を防ぐ |
| **資料の性格の伝達** | 黒塗り・手書き・図版など、資料の特徴をひと目で示す |
| **引用の透明性** | どのページから情報を取ったかを視覚的に示す |

**重要な前提：**  
画像は「資料の雰囲気・実在感」を伝えるものであり、画像単体で内容を断定したり、センセーショナルな演出に使ったりしない。記事の主役はあくまでテキスト（翻訳・要約）である。

## 2. 使ってよいページ

### 2-1. 表紙ページ
- 資料名・発行機関・日付が一目でわかる
- 「どの機関が出した何という資料か」を読者に示す最も適切なビジュアル
- **推奨度：高**

### 2-2. 冒頭ページ（1〜3ページ目）
- 資料の目的・宛先・分類マーク（SECRET / FOR OFFICIAL USE ONLY 等）が確認できる
- 資料の格と性格を伝えるのに有効
- 分類マークが残っている場合は「現在は機密解除済み」をキャプションで補足する
- **推奨度：高**

### 2-3. 黒塗りが多いページ
- 「情報が存在するが開示されていない」という事実そのものを示す
- 政府の情報公開の限界・透明性の問題を視覚的に伝えられる
- センセーショナルな切り取りにならないよう、「黒塗りは標準的な機密保護処理」とキャプションで補足する
- **推奨度：中（1〜2枚まで）**

### 2-4. 手書きページ
- メモ・注記・署名など、資料の人間的な側面を伝える
- 読者の興味を引きやすい
- 手書き文字の内容が読み取れる場合は翻訳・補足を添える
- 個人名・署名が判別できる場合は利用を慎重に判断する（→ 項目3参照）
- **推奨度：中**

### 2-5. 図版・写真ページ
- 地図・図解・フォーメーション図・センサー図など、内容理解を助けるもの
- 「見るだけで情報が伝わる」ページとして有効
- UAP の写真・映像スクリーンショットは扱いに注意（→ 項目7参照）
- **推奨度：中（内容に関係するものに限る）**

### 2-6. OCR Challenge 候補ページ
- `worker_outputs/ocr_challenge_candidates_20260529.csv` に記録された低信頼度ページ
- 「OCR でテキスト化が難しかったページ」＝手書き・図版・印刷品質が低いページ
- これらは逆に「資料の生々しさ・年代感」を伝えるビジュアルとして活用できる
- テキスト化できていない場合は「テキスト抽出困難ページ。内容は翻訳に含めていない」と明記する
- **推奨度：ケースバイケース**

## 3. 使わない方がよいページ

### 3-1. 個人情報が強いページ
具体的には以下を含むページは原則除外：
- 個人の氏名・階級・所属部署（特に事件関係者・目撃者）
- 住所・連絡先・社会保障番号等
- 署名が明確に読み取れるページ（著名な人物の場合は文脈で判断）

### 3-2. 意味が読み取れないページ
- 白紙・ほぼ黒塗り・印刷不良で内容が全く不明なページ
- 記事の流れと無関係なページ
- 「なんとなく雰囲気を出す」だけの目的では使わない

### 3-3. 煽りに見える切り取り
- 文脈なしに「UFO が写っている」ように見えるページの単独使用
- 黒塗りを「隠蔽の証拠」として演出的に使うこと
- 分類マークだけをクローズアップして「極秘文書！」と印象操作すること

**方針：** 切り取り方によって読者が誤解する可能性があると判断した場合は、そのページは使わないか、十分なキャプションを付ける。

## 4. キャプション方針

すべての画像に以下の要素を含むキャプションを付ける。

### 必須要素

| 要素 | 内容 |
|------|------|
| **資料の一部である旨** | 「〇〇資料（p.X）より」のように出典を明示 |
| **視覚的参考である旨** | 「内容の視覚的な参考として掲載」と一言添える |
| **断定しない旨** | 「この画像のみで内容を断定するものではありません」 |
| **機密解除の補足** | 機密マークが見える場合は「現在は機密解除済み」を添える |

### キャプション文例

```
▲ 〇〇報告書（1976年）表紙。米国防総省発行。
現在は機密解除済み。内容の視覚的な参考として掲載。
この画像のみで内容を断定するものではありません。
```

```
▲ 同資料 p.12。黒塗り処理が施されたページ。
黒塗りは標準的な機密保護処理であり、隠蔽を示すものではありません。
```

## 5. note 記事での配置案

### 基本構成

```
【タイトル】
【リード文：資料の概要・背景】

▼ [表紙画像]
キャプション

【セクション1：資料の性格・発行経緯】
  本文テキスト

▼ [特徴的なページ画像（黒塗り・手書き・図版など）]
キャプション

【セクション2：主要な記述の翻訳・要約】
  本文テキスト

【まとめ・所感】
【出典情報】
```

### 配置ルール

| ルール | 内容 |
|--------|------|
| 1記事あたりの画像数 | 2〜4枚を目安。多すぎると記事が重くなる |
| 画像サイズ | note の推奨幅に合わせてリサイズ（横幅 1200px 程度） |
| 配置位置 | セクションの冒頭または末尾。本文の途中に挿入しない |
| alt テキスト | 「〇〇資料 p.X 表紙」など簡潔に |

## 6. source URL / file_name / page_number の明記

画像を使用する際は、記事内または末尾の出典リストに以下を必ず記載する。

### 記載フォーマット

```
【出典】
- 資料名：〇〇 UAP Mission Report
- ファイル名：xxx_yyy_zzz.pdf
- ページ：p.1（表紙）、p.12
- 入手元：AARO公式 / FOIA公開資料 / (source_registry.csv 参照)
- 機密解除状況：機密解除済み（Declassified）
```

### 管理ルール

- 使用した画像・ページ番号は `worker_outputs/` 配下の素材カード CSV に記録する（将来実装）
- `source_registry.csv` の `source_url` 列を出典 URL として参照する
- ページ番号は PDF の実ページ番号（page_images/ のファイル名に対応）を使う

## 7. Codex 監査観点

記事公開前の Codex レビューで、以下の観点を確認する。

| 確認項目 | 内容 |
|----------|------|
| **個人情報リスク** | 個人名・住所・署名が判読できる画像が含まれていないか |
| **断定表現リスク** | キャプションや本文が「画像が〇〇を証明している」等の断定になっていないか |
| **煽り表現リスク** | 黒塗り・機密マーク・UAP画像の演出的な使い方になっていないか |
| **出典記載** | ファイル名・ページ番号・入手元が明記されているか |
| **機密解除の確認** | 現在も機密扱いの資料の画像を誤って使っていないか |
| **AARO スタンス整合** | 画像の選び方・キャプションが中立的な報道スタンスを維持しているか |

### Codex 監査チェックリスト（記事ごと）

```
□ 使用画像にPII（個人特定情報）が含まれていないか確認した
□ すべての画像にキャプション（出典・視覚参考・非断定）を付けた
□ 機密解除済みの資料のみから画像を使用した
□ source_registry.csv / file_name / page_number を記事に明記した
□ 画像だけを見て誤解を招く表現がないか確認した
□ AARO 公式スタンスと矛盾する表現がないか確認した
```
