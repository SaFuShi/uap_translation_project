**作成日：** 2026-05-15
**ステータス：** 確定版 v1.0
**用途：** 今後の制作・運用・収益化の設計思想書 / 新chat引継ぎ基準文書

## 0. 最重要前提：このプロジェクトの大命題

**このプロジェクトの根本目的は、AIを活用して、一人で継続可能な収益構造を作ることである。**

UAP（未確認空中現象）公開資料そのものが目的ではない。UAP資料は、以下を検証するための「題材」である。

- AI活用・プロンプト設計
- 公文書解析・OCR・翻訳
- メディア化（note・YouTube）
- ローカルLLM運用・AIエージェント化
- note運用による収益構造の構築

### 重要原則：目的と手段を混同しない

「研究として面白い」は判断基準にしない。
「継続可能な収益モデルとして成立するか」を最優先判断基準とする。

面白そうでも収益に結びつかない作業は後回しにする。
逆に、地味でも収益化に直結する作業を優先する。

## 1. Phase1（AI暫定版）の役割と成果

### Phase1の位置づけ

AI暫定版は「完成版」ではない。

その役割は以下に限定される。

- 速報・索引としての機能
- 原文（war.gov）への入口の提供
- 116件の全体可視化
- ファイル整理とsource_registry構築
- AI運用の実験・ノウハウ蓄積

### Phase1で達成したこと

| 項目 | 内容 |
|---|---|
| 記事化 | 116件すべて記事化 |
| 公開 | 108件をnoteに公開 |
| 管理台帳 | source_registry.csv整備（119エントリ） |
| 重複管理 | duplicate 2件検出・処理済み |
| 用語標準化 | AARO/USCENTCOM/MISREP等の標準補足一覧整備 |
| レビュー運用 | Codex監査・ChatGPT最終確認 |
| ログ化 | NotebookLMログ・Git管理 |

### Phase1で見えた課題

- **OCR限界：** 全体の半数近くがスキャン画像PDFで内容抽出不可
- **AI hallucination：** 原文にない情報を自動追加する問題が繰り返し発生
- **断定表現問題：** 「報告書に記されていること」と「事実」の区別が曖昧になりやすい
- **軍事用語ブレ：** 略語の訳が毎回ブレる（中盤以降は標準化で改善）
- **読み物として弱い：** 客観性優先の結果、引き込まれない記事になっているものがある
- **工数過多：** OCR→ドラフト→レビュー→公開の各ステップに人間判断が必要
- **トークンコスト問題：** 大量PDFを外部AIに送るとコスト爆発

## 2. Phase2（詳細版）の役割

### 詳細版は「AI要約」ではない

詳細版の役割は「資料を読む」こと。具体的には以下を行う。

- 原文の引用と詳細解析
- 複数資料の横断比較
- 時系列整理
- 画像比較・IR映像解析
- OCR補正・手書き解析
- 背景・文脈の整理
- 用語解説
- 読み物としての完成

### 重要：1ファイル = 1記事にこだわらない

Phase1はファイル単位で1記事を作る方針だった。
Phase2では「複数資料横断」を基本とする。

同一シリーズのファイル、関連するテーマのファイルは、まとめて1記事にした方が読者にとって価値が高い場合が多い。

---

## 3. 詳細版の分類軸

Phase2では、ファイル単位ではなくテーマ・事件・機関・時代で束ねて記事化する。

### A. テーマ軸（最有力）

| テーマ | 対象資料例 |
|---|---|
| 白色光球 | USCENTCOM MISREP・FBI写真シリーズ |
| 円盤形状 | DoW歴史的文書・FBI捜査ファイル |
| IR映像 | FBIフォトBシリーズ（1999年） |
| フーファイター | SHAEF電文・1944〜1945年ドイツ |
| FBI内部対応 | 62-HQ-83894シリーズ（1947〜1968年） |
| AARO未解決 | PR31/PR32/PR33参照案件 |
| レーダー探知 | 各種MISREP |
| 軍事施設周辺 | 地域別MISREP横断 |

### B. 事件軸

特定の事件や出来事を軸に、関連する複数ファイルを横断してまとめる。
例：「1999 IRシリーズ」「シリア2024年10月事案」「アラビア海事案群」

### C. Department軸

発行機関別にまとめる。
FBI / 国防総省（DoW/DoD） / NASA / 国務省（DoS） / AARO

### D. 時系列軸

年代別にまとめる。
1940年代 / 1950年代 / 1960〜1970年代 / 現代（2020年代）

### E. メディア軸

資料の種類別にまとめる。
IR映像 / 写真 / 手書きメモ / OCR困難資料 / 動画

### 現時点の方向性

**最有力：テーマ軸 + 事件軸の組み合わせ**

## 4. noteとYouTubeの役割分離

### note（有料想定）= 本編

| 機能 | 内容 |
|---|---|
| 目的 | 調査レポート・深掘り解説 |
| 内容 | 原文比較・読み解き・背景整理・保存価値 |
| 価値 | 「この記事にしかない分析」が有料の根拠 |

### YouTube = 入口・導線

| 機能 | 内容 |
|---|---|
| 目的 | 集客・興味喚起 |
| 内容 | ダイジェスト・映像体験・雰囲気 |
| 役割 | noteへの誘導。「続きはnoteで」 |

### 重要原則：YouTubeでnoteの価値を潰さない

動画で「全部説明しない」。
noteが本編であり、YouTubeはその予告編・導線として機能させる。

詳細分析・原文引用・用語解説はnoteにのみ掲載する。

## 5. 詳細版の記事構造案

詳細版の各記事は以下の構成を基本とする。

| 順序 | セクション | 内容 |
|---|---|---|
| 1 | Hook | 何が起きたか。読者を引き込む導入 |
| 2 | まず結論 | 何が分かったか。結論を先に提示 |
| 3 | 資料解説 | 機関・年代・文脈の説明 |
| 4 | 原文引用 | 重要な記述を原文から直接引用 |
| 5 | AI解析 | 比較・時系列・関連資料との照合 |
| 6 | 不明点 | 断定できないことを明示する |
| 7 | 関連資料 | 横断導線・関連記事へのリンク |
| 8 | まとめ | 読後感・次の記事への橋渡し |

---

## 6. ディスクレーマー方針

詳細版には必ずディスクレーマーを入れる。

### 方向性：「責任回避」ではなく「資料読解の限界説明」

読者に対して、この記事が何を根拠にして書かれており、どこに限界があるかを誠実に伝えることを目的とする。

### 必須記載内容

- OCR誤認識の可能性（スキャン画像由来の誤読）
- AI解析の誤差（hallucination・翻訳ブレ）
- 翻訳・解釈の差異（原文の確認を推奨）
- 推論と事実の分離（「報告書にはこう記されている」を明示）
- 陰謀論化しない姿勢の明示

## 7. AI役割分担

Phase2では、各AIツールの役割を明確に分離する。

### ChatGPT = 編集長

| 役割 | 具体的な作業 |
|---|---|
| 構成・読み物化 | 記事構成の設計・導入の磨き上げ |
| note戦略 | タイトル設計・有料価値の設計 |
| メディア戦略 | YouTube展開・動画シナリオ |
| 最終監査 | 記事全体のトーン・品質確認 |

### Claude Code = 調査アシスタント

| 役割 | 具体的な作業 |
|---|---|
| データ整理 | OCR・metadata整理・source_registry管理 |
| ドラフト生成 | 原文ベースのAI要約ドラフト |
| 画像整理 | frame抽出・PDF→PNG変換 |
| Git運用 | バージョン管理・ログ化 |

### Codex = 監査・検証

| 役割 | 具体的な作業 |
|---|---|
| 原文照合 | ドラフトと原文の整合性確認 |
| hallucination検出 | 原文にない記述の特定 |
| CSV検証 | source_registryの構造チェック |

### ローカルLLM / AIエージェント = 24時間稼働する整理工場

| 役割 | 具体的な作業 |
|---|---|
| 前処理 | OCR前処理・PDF→PNG変換 |
| 重複検出 | MD5/ハッシュによるduplicate確認 |
| クラスタリング | 類似資料のグルーピング |
| metadata抽出 | 機関・年代・キーワードの自動抽出 |
| テンプレート生成 | ドラフト生成のための前準備 |

## 8. ローカルLLM活用方針

### 問題：全PDFを外部AIに送るとコスト爆発

**悪い構造：** 全PDF → ChatGPT / Claude → コスト爆発・プライバシーリスク

**理想構造：**
```
ローカルで前処理・分類・重要部分抽出
↓
抽出した重要部分のみを高性能AIへ
↓
高性能AIで「意味生成」
```

### 役割分離の原則

| 処理 | 担当 |
|---|---|
| 整理・分類・前処理 | ローカルLLM / ローカルスクリプト |
| 意味生成・解析・編集 | 外部高性能AI（ChatGPT / Claude） |

### 今後の整備対象

- 画像OCRパイプライン（スキャン画像対応）
- 手書きメモ解析
- IRカメラ映像のframe抽出
- 用語補完・自動タグ付け

## 9. 詳細版制作Pipeline（構想）

```
Step 1  PDF/資料投入
         ↓
Step 2  ローカル自動分類
         （OCR可否 / 画像系 / IR / 手書き / FBI / MISREP）
         ↓
Step 3  PDF → PNG変換
         ↓
Step 4  OCR / frame抽出
         ↓
Step 5  metadata整理
         （機関・年代・インシデント日時・場所）
         ↓
Step 6  関連資料クラスタリング
         （テーマ / 事件 / シリーズでグループ化）
         ↓
Step 7  Claude Code 下調査
         （資料読解・ドラフト生成・整合性チェック）
         ↓
Step 8  Codex 監査
         （hallucination検出・原文照合・CSV検証）
         ↓
Step 9  ChatGPT 編集
         （構成・読み物化・タイトル・有料価値設計）
         ↓
Step 10 note公開
         ↓
Step 11 YouTube化（必要に応じて）
```

## 10. 動画化方針

### 動画はnoteの無料コピーにしない

| 媒体 | 役割 |
|---|---|
| YouTube | 興味喚起・雰囲気・導線。「続きはnoteで」 |
| note | 分析・深掘り・解説・保存価値。本編 |

### 動画の方向性

- AIニュースショー形式（AIアンカーによる解説）
- frame比較・矢印・IR解析の視覚的提示
- 短尺導線動画（2〜5分）
- 「全部説明しない」ことを徹底する

---

## 11. 収益化方針

### 重要原則：全部を高品質化しない

リソースは有限である。

**優先高（重点強化）：**
- 読み物になる資料
- 画像・映像がある資料
- 比較・対比ができる資料
- 時系列が整理できる資料
- 一般読者の興味を引く資料

**優先低（後回し）：**
- OCR不可のみで情報ゼロの資料
- 管理目的のみの記録（AI暫定版で完結）

### 収益構造の基本設計

```
YouTube（無料）
    ↓ 導線
note AI暫定版（無料 or 低額）
    ↓ 導線
note 詳細版（有料）
```

詳細版の有料価値は「この記事にしかない分析・読み解き」で作る。
汎用的なAI要約では有料価値は生まれない。

## 12. 最初の詳細版候補

### 最有力：1999 IRシリーズ

FBI写真分析資料 Bシリーズ（fbi-photo-b1〜b24相当）

**選定理由：**

| 理由 | 内容 |
|---|---|
| 画像比較できる | IRカメラ映像の静止フレームが複数存在 |
| note向き | 読み物・解説記事として成立する |
| YouTube向き | 視覚的なframe比較が動画に向く |
| 時系列ある | 1999年という明確な年代 |
| 関連ファイル多い | シリーズとして横断できる |
| OCR不要 | スキャン問題なし |
| 「読む」価値がある | 原文比較・画像解析の余地がある |

**他の候補（次点）：**
- SHAEF フーファイター（1944〜1945年）
- FBI 62-HQ-83894 シリーズ（1947〜1968年）
- USCENTCOM MISREP シリア・アラビア海群

## 14. 最重要原則（再掲）

**このプロジェクトの目的は：**
**AIを活用して、一人で継続可能な収益構造を作ることである。**

UAPは題材である。目的と手段を混同しない。

「面白いから調査する」ではなく、「収益に結びつくから調査する」。

AIは万能ではない。Phase1で実証した通り、AIで大量整理はできるが、人間のレビューなしには「正確で読ませる記事」にはならない。AIを礼賛せず、コストと品質のバランスを常に意識して運用する。
