## 0. 設計大前提

### プロジェクト目的（再確認）

```
1. 公開資料を日本語で紹介する
2. 元ソースへ辿れるようにする
3. できるだけ自動化する
4. 読者にとって読み物として成立させる
5. コンテンツとして継続可能にする
```

### ファイル ≠ 記事の原則

```
レイヤー1（資料管理）: 1ファイル = 1管理単位（files_catalog管理）
レイヤー2（公開記事）: 1記事   = 1テーマ（複数ファイルを統合可）
レイヤー3（研究資産）: 記事内に関連ソースを必ず明記
```

### 記事化の判定基準

| 条件 | 判定 |
|---|---|
| 独自の事案・独自の読者価値がある | 単独記事化 |
| 同一事案・同一調査の複数ファイル | 統合記事化 |
| 単独では記事として成立しない補足材料 | 付属素材 |
| より大きな記事群に付属する参考文献 | 参考資料 |
| 内容精査が未完了 | 記事化保留 |
| 記事化しても読者価値がない | 対象外 |

## 2. 分類ルールと6分類の定義

| 分類 | 定義 | article_id | 記事化作業 |
|---|---|---|---|
| **単独記事** | 1ファイル = 1記事。固有の事案・独自の読者価値あり | 新規発番（#2_090〜） | ドラフト作成 → Codex → note公開 |
| **統合記事** | 複数ファイル = 1記事。同一事案・同一調査 | 新規発番（代表1件） | 統合ドラフト作成 → Codex → note公開 |
| **付属素材** | 既存記事内に「関連ソース」として掲載。単独記事なし | article_id不要（ファイル管理のみ） | 関連記事へのリンク・言及追記 |
| **参考資料** | 内容言及のみ（全文掲載なし） | article_id不要 | 関連記事の参考文献欄に記載 |
| **記事化保留** | 内容精査未完了、またはHOLD状態 | 予約発番（HOLD） | 後日 |
| **対象外** | 記事化価値なし（重複/破損/非UAP） | なし | 不要 |

### 読者体験が最も良い構成は何か

```
【優先順位】
1. 事案の理解 = VID映像 + 対応PDF（付属素材として同一記事内に参照）
2. 文書内容 = PDF記事は「1記事1テーマ」で整理（複数文書を統合）
3. 歴史的文脈 = 歴史的文書は時代順・テーマ順で配置
4. 発見の連鎖 = 記事間クロスリンク（同一事案の映像記事↔書類記事）
```

→ ファイル → 記事 の双方向参照が常に確保される
