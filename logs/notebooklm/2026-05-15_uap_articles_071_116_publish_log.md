## 4. 重要な改善点

### A. PDFタイプ分類仕様の確立（TYPE-A〜G）

これまで暗黙的に行っていたPDFの分類を、7種類の公式タイプとして定義した。

| タイプ | 内容 |
|---|---|
| TYPE-A | IRカメラ映像の静止フレーム |
| TYPE-B | 一部リダクション（黒塗り）あり |
| TYPE-C | 画像・写真のみ |
| TYPE-D | MISREP（任務報告書）形式 |
| TYPE-E | 歴史的背景文書・書簡集 |
| TYPE-F | 外交電報 |
| TYPE-G | FBI断片資料 |

今後のドラフト生成では、このタイプに応じたテンプレートを使用する。

### B. 軍事略語の標準補足ルールの確立

記事内で使用する軍事・行政略語の日本語補足を統一した。

| 略語 | 標準補足 |
|---|---|
| AARO | 全領域異常解決局（米国防総省のUAP調査組織） |
| USCENTCOM | 米国中央軍（中東・中央アジア担当） |
| MISREP | 任務報告書 |
| GENTEXT | 一般テキスト欄 |
| FMV | フルモーションビデオ（動画） |
| positive identification | 確定識別 |
| platform | 米軍側の機材・システム（機種断定禁止） |

`platform` については、具体的な機体名が不明な場合に断定表現を使わないというルールも定めた。

### C. OCR不可文書のドラフト表現の統一

文書の本文がスキャン画像のためテキスト抽出できない場合の表現を統一した。

- 旧（禁止）：「ファイル名以外の情報源がない」
- 新（採用）：「ファイル名およびwar.gov公開説明文から確認できる情報」
- 「OCR不可」→「有意なテキスト抽出が困難」

### D. war.gov起因の重複PDF検出と対処法の確立

war.govが同一内容のPDFを異なるURLで公開しているケースを発見した（#069/#069b）。

- MD5ハッシュを使って同一ファイルを検出する手順を整備
- `audit_checklist_v1.md` にMD5クロスチェック項目を追加（P1-5）
- 重複ファイルは `source_registry.csv` に `duplicate_of_XXX` ステータスで記録する

## 5. 発生した問題と対処

### 問題1：#100/#101 のCSV行が結合してしまった

**発生状況：** Pythonスクリプトで #101〜#116 を source_registry.csv に追記した際、#100の末尾に改行が入らず #101 が同じ行に結合してしまった。

**症状：** `grep "^#101"` で #101 の行が見つからない。

**対処：** Pythonの文字列置換で `...1947-1968年UFO記録` の直後に改行を挿入して修正。

**教訓：** CSVへの追記は改行有無を必ず確認する。

---

### 問題2：#093 のCSV行がカンマ含みファイル名でフィールド崩れ

**発生状況：** `dow-uap-d32-mission-report,-syria-october-2024.pdf` というファイル名にカンマが含まれているため、CSVとして読み込むと13フィールドに分割されてしまっていた（正常は11フィールド）。

**症状：** CSVパーサーがファイル名の途中のカンマをフィールド区切りと誤認識する。

**対処：** ファイル名フィールドとURLフィールドをダブルクォートで囲んだ（`"dow-uap-d32-mission-report,-syria-october-2024.pdf"`）。

**教訓：** ファイル名にカンマが含まれる場合はCSV登録時に必ずクォートする。#043 は当初から正しくクォート済みだったが #093 は見落としていた。

---

### 問題3：記事番号の誤入力（#112）

**発生状況：** ユーザーが「2」とだけ送信し、#112公開URLが得られなかった。

**対処：** #112 を誤って更新せず保留。その後ユーザーが正しいURLを再送し、正常に更新。

---

### 問題4：review_standard_v1.md の編集競合

**発生状況：** 用語標準化の編集中に、フック（linter）が自動的にファイルを変更したため Edit ツールが「ファイルが変更されました」エラーを返した。

**対処：** フックによる変更内容を確認したところ、意図した変更が正しく適用済みだったため、追加の編集は不要と判断した。

## 6. 今後の運用ルール

### source_registry.csv 管理
- ファイル名にカンマが含まれる場合は、pdf_file_name および source_url フィールドをダブルクォートで囲む
- 新規PDF追加前にMD5重複チェックを実施する（`scripts/check_duplicate_source.py`）
- 追記後は `#NNN` 行が独立した行になっているか確認する

### ドラフト生成
- PDFを受け取ったらまずタイプ分類（TYPE-A〜G）を確認する
- OCR不可の場合はwar.gov公開説明文を情報源として明記する
- 軍事略語は初出のみ日本語補足を付ける（繰り返し補足しない）

### レビュー工程（#030以降に適用）
- Phase 1：Provenanceチェック（情報源の根拠確認）
- Phase 2：日本語UXレビュー（読みやすさ・誤解のない表現か）

### 用語の断定回避
- 具体的な機種名が確認できない場合は `platform`（米軍側の機材・システム）を使用
- OCR不可文書では推測・断定表現を使わない
